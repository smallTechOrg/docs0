Gmail

Gmail needs a one-time setup before it can be connected.

Add DOCS0_ENCRYPTION_KEY to the .env file and restart docs0. It is 32 random bytes in base64; make one with openssl rand -base64 32. docs0 encrypts the key you paste with it.

Gmail is not connected.

docs0 reads the mailboxes you choose, and nothing else. docs0 can read every mailbox you add, but a person's mail is only ever shown to that person, in their own direct message with docs0 (plus anyone you list for a shared inbox such as support@). It is never used in a channel or for anyone else. docs0 only reads mail: it cannot send, change or delete anything. Only the last 90 days are indexed, without spam, trash, drafts, Promotions, Social and Forums.

You need to be a Google Workspace administrator for these steps.

  1. In Google Cloud Console make a project (or pick one), then under APIs & Services → Library turn on the Gmail API. If you want to load your people from Google Workspace later, turn on the Admin SDK API too.
  2. Under IAM & Admin → Service Accounts create a service account (any name, no roles needed). Open it, choose Keys → Add key → Create new key → JSON. A file downloads.
  3. Open that file in a text editor, copy everything in it and paste it below. docs0 checks it and stores it encrypted. It is never shown again.
  4. After saving, this page shows the service account's client ID and the last step: letting Google Workspace trust the account.

Let Google Workspace trust this account (one time, as an administrator):

  1. Open the Admin console → Security → Access and data control → API controls → Domain-wide delegation and choose Add new.
  2. Client ID: copy this number.
  3. OAuth scopes: https://www.googleapis.com/auth/gmail.readonly
    Only if you want to load your people from Google Workspace below, add a second scope, separated by a comma: https://www.googleapis.com/auth/admin.directory.user.readonly
  4. Choose Authorise, then come back and press Check access below.
